# المعمارية

وثيقة للمطوّر: كيف بُني «سجلي»، ولماذا، وأين تجد كل شيء.

## نظرة عامة

```
المتصفح (React SPA)  ──HTTP/JSON──▶  Fastify (Node 22)  ──▶  SQLite (ملف واحد)
      │                                   │
      │                                   ├─▶ Chromium بلا واجهة  (PDF)
      └── src/shared (عقود مشتركة) ◀──────┴─▶ ExcelJS            (Excel)
```

- **عملية واحدة** تخدم الواجهة المبنية (`dist/web`) والـAPI (`/api/*`) معًا — لا حاجة لخادم ويب منفصل ولا لقاعدة بيانات منفصلة.
- **`src/shared`** هو الجسر: مخططات Zod، الثوابت، أنواع الـDTO، ودوال حساب الدرجات النقية. يستوردها الخادم والواجهة معًا، فما يراه المعلم على الشاشة هو نفسه ما يُطبع في التقرير.

## قاعدة البيانات

**SQLite** عبر `better-sqlite3` (متزامن — يناسب الحمل ويبسّط المعاملات) و**Drizzle ORM** للأنواع والاستعلامات. إعدادات الاتصال (`db/client.ts`):

| الإعداد | السبب |
|---|---|
| `journal_mode = WAL` | قراءات لا تحجبها الكتابة، ونسخ احتياطي متّسق أثناء التشغيل |
| `synchronous = FULL` | لا يضيع آخر تعديل عند انقطاع الكهرباء (نفضّل الأمان على بضع مللي ثانية) |
| `foreign_keys = ON` | سلامة العلاقات وحذف متسلسل (حذف الشعبة/المعلم يحذف تابعاتها) |
| `secure_delete = ON` | الصفحات المحذوفة تُصفَّر فلا تبقى بيانات طلاب محذوفين في الملف |
| `busy_timeout = 5000` | انتظار قصير بدل خطأ فوري عند قفل مؤقت |

### الجداول (19)

| المجال | الجداول |
|---|---|
| الهوية | `users` · `sessions` · `user_settings` |
| الأكاديمي | `academic_years` · `terms` · `subjects` · `sections` · `assignments` (شعبة × مادة) |
| الطلاب | `students` · `enrollments` (طالب في شعبة بعام) · `student_notes` |
| التخطيط | `timetable_slots` · `lesson_plans` · `tasks` |
| التقويم | `skills` · `assessments` · `assessment_skills` · `assessment_results` |
| التدقيق | `audit_log` |

مبادئ المخطط:

- **كل جدول بيانات يحمل `owner_id`** (المعلم) بمفتاح أجنبي `ON DELETE CASCADE`. حذف حساب = محو كل بياناته.
- معرّفات **UUID** عشوائية (غير قابلة للتخمين)، التواريخ `YYYY-MM-DD` نصوص، الطوابع ISO-8601.
- قيود `UNIQUE` و`CHECK` ومفاتيح أجنبية تحمي السلامة **في القاعدة نفسها** حتى لو أخطأ التطبيق.
- الطالب كيان مستقل يمكن تسجيله في شعب مختلفة عبر الأعوام (`enrollments`) — فتاريخه يبقى متصلًا عند الترقية.
- `lesson_plans.search_text` عمود مُطبَّع (بلا تشكيل/همزات) يُحدَّث عند الحفظ لتمكين بحث عربي سريع.

### الهجرات

`npm run db:generate` يولّد ملف SQL مُرقَّمًا من تعديلات `schema.ts` (drizzle-kit). تُطبَّق تلقائيًا عند بدء الخادم، وقبلها — إن كانت هناك بيانات وهجرات معلّقة — **تُؤخذ نسخة احتياطية `pre-migration`** تلقائيًا.

> الهجرة الحالية واحدة (`0000_init.sql`) لأن المشروع لم يُنشر بعد. **بعد أول نشر حقيقي لا تعدّل هجرة موجودة أبدًا**؛ ولّد هجرة جديدة.

### الانتقال إلى PostgreSQL (إن لزم)

الاستعلامات كلها عبر Drizzle داخل `modules/*/service.ts`، والاتصال في `db/client.ts` فقط. الانتقال يعني: تبديل مشغّل Drizzle (`pg-core`) وإعادة كتابة `schema.ts` بأنواع PostgreSQL، وتحويل الاستدعاءات المتزامنة `.get()/.all()/.run()` إلى `await`، وإعادة كتابة النسخ الاحتياطي (`pg_dump`). عمل حقيقي لكنه محدود الموضع — لذلك لم نُدخل تجريدًا مبكرًا لا حاجة له الآن.

## العزل بين المعلمين

القاعدة الذهبية: **كل دالة خدمة تأخذ `(db, ownerId, …)` وكل استعلام يُقيَّد بـ`owner_id`.**

- `lib/context.ts → getCtx(req)` يعطي `{ db, ownerId, user }` للمسارات المصادَق عليها.
- `modules/_shared/owned.ts` يحوي `requireStudent/requireSection/…` وكلها تتحقق من الملكية وترمي **404** (وليس 403) عند عدم الملكية، حتى لا يُكشف وجود بيانات غيره.
- اختبارات التكامل تجرّب فعليًا الوصول لموارد معلم آخر عبر كل المسارات.

دور **المدير** يدير الحسابات والنسخ الاحتياطي وسجل العمليات، ولا يرى بيانات الطلاب لدى المعلمين عبر واجهات التطبيق (وهو معلم أيضًا لحسابه الخاص). **تنبيه:** صلاحية النسخ الاحتياطي تتيح له تنزيل نسخة كاملة تحوي بيانات الجميع، فهو دور عالي الامتياز يُمنح بحذر (انظر [SECURITY](SECURITY.md#نموذج-الأدوار)).

## الطبقات في الخادم

```
routes.ts   ← HTTP فقط: تحقق Zod من المدخلات، استدعاء الخدمة، شكل الاستجابة
service.ts  ← منطق الأعمال والاستعلامات (دوال نقية على db/ownerId) — قابلة للاختبار بلا HTTP
lib/*       ← أخطاء، جلسات، كلمات مرور، تدقيق
```

- **الأخطاء:** `AppError(status, code, رسالة عربية, fields?)` تُحوَّل مركزيًا إلى `{ error: { code, message, fields } }`. الواجهة توزّع `fields` على حقول النموذج تلقائيًا (`lib/forms.ts`).
- **التحقق:** `parse(schema, data)` يرمي 400 برسائل عربية (خريطة أخطاء Zod عربية في `shared/schemas/common.ts`).
- **السجل:** `audit(req, …)` يسجّل الحدث والحساب والعنوان — **بلا أسماء طلاب أو درجات**.

## قواعد حساب التقويم المستمر

(`src/shared/gradebook.ts` — دوال نقية تُستعمل في التقارير وفي الشبكة اللحظية)

| حالة الرصد | أثرها على المجموع والنسبة |
|---|---|
| درجة مرصودة | تضيف `(الدرجة ÷ العظمى) × الوزن` للمحقَّق، والوزن للممكن |
| **غائب** (`غ`) | تُحتسب صفرًا: الوزن يدخل في الممكن فقط |
| **معذور** (`ع`) | تُستثنى من البسط والمقام |
| لم تُرصد | تُستثنى وتُعدّ «غير مكتملة» (تظهر في لوحة التحكم) |
| تقويم إتقان (1–4) | لا يدخل المجموع؛ يُستعمل لتتبع المهارات |
| تقويم «لا يُحتسب» | لا يدخل المجموع |

`النسبة = المحقَّق ÷ الممكن × 100`، والمستوى يُحدَّد من حدود يضبطها المعلم (الافتراضي: 90/75/60/50/0). الأرقام تُقرَّب لخانتين عشريتين كحد أقصى، وتُعرض النسب بخانة عشرية واحدة في كل مكان (شاشة وتقرير) لتوحيد الأرقام.

## التقارير

خط إنتاج واحد بمحتوى وسيط:

```
builders.ts  ──▶  ReportDoc (كتل: عنوان، جدول، حقول، بطاقات…)
                      │
                      ├─▶ html.ts  : قالب HTML بهروب تلقائي + خطوط IBM Plex Sans Arabic مضمّنة base64
                      │              ├─▶ المعاينة في الواجهة (iframe بـsandbox)
                      │              └─▶ pdf.ts : Chromium بلا واجهة (بلا JS، وكل طلب شبكة مُجهَض)
                      └─▶ xlsx.ts  : ExcelJS بأرقام حقيقية وورقة RTL
```

- المحتوى يُبنى **مرة واحدة** فتتطابق نسخ HTML وPDF وExcel.
- أمان PDF: يُحمَّل HTML من الذاكرة، **JavaScript معطّل**، وكل طلب شبكة غير `data:` يُلغى (لا SSRF حتى لو دخل محتوى خبيث للنص).
- الخطوط مضمّنة داخل HTML: لا تعتمد النتيجة على خطوط الخادم.
- ترقيم الصفحات بـ`@page` margin boxes.
- يُعاد استعمال متصفح واحد ويُغلق بعد 5 دقائق خمول، بحد أقصى متزامن 2.

## النسخ الاحتياطي

انظر [BACKUP.md](BACKUP.md). باختصار: واجهة SQLite `backup()` (نسخة متّسقة أثناء التشغيل) ← `integrity_check` ← تشفير اختياري AES-256-GCM (مفتاح مُشتق بـscrypt، ترويسة `SJLBK1`) ← احتفاظ ذكي. الاستعادة تفحص الملف (سلامة، أنه من «سجلي»، وأنه ليس من إصدار أحدث) ثم تأخذ نسخة `pre-restore` ثم تستبدل القاعدة المفتوحة بتبديل ملف متزامن.

## الواجهة

- **التوجيه:** React Router 7، كل صفحة `lazy` (تقسيم الحزمة)، حارس `RequireAuth` يتعامل مع: الإعداد الأول، غير المسجّل، وإلزام تغيير كلمة المرور.
- **البيانات:** TanStack Query؛ مفاتيح الاستعلام مركزية في `lib/queries.ts`، والطفرات عبر `useAppMutation` (إبطال + إشعار نجاح/خطأ عربي موحّد).
- **النماذج:** React Hook Form + مخططات Zod المشتركة نفسها المستعملة في الخادم → قاعدة تحقق واحدة.
- **التصميم:** رموز CSS (ألوان/ظلال/أنصاف أقطار) مربوطة بـTailwind عبر `@theme inline`، وسمة داكنة بـ`data-theme`. استُعملت **الخصائص المنطقية** (`ms/me/ps/pe/start/end`) بدل left/right فيعمل RTL طبيعيًا. الخط: IBM Plex Sans Arabic (محلي عبر fontsource، بلا CDN).
- **الأرقام:** تفضيل لكل معلم (لاتينية/هندية) يُطبَّق في الشاشة والتقارير (`useFmt`).
- **سمة بلا وميض:** `public/theme-init.js` سكربت خارجي صغير (لأن CSP تمنع المضمَّن) يضبط السمة قبل الرسم.

### شبكة الدرجات (القلب)

مصدر الحقيقة للخلايا `ref` يُحدَّث عبر دالة واحدة ثم يُطلب رسم جديد؛ كل خلية لها `ver`/`dirty`/`saved`/`failed`/`invalid`. الحفظ مؤجَّل 600ms ومُجمَّع في **طلب واحد لكل تقويم**، ويُتحقَّق من **الدفعة كلها قبل أي كتابة** (ذرّية). تُحفظ الخلية الفارغة كحذف للنتيجة. عند فشل الشبكة تبقى الخلية «غير محفوظة» وتُعاد المحاولة عند عودة الاتصال، ويُمنع إغلاق الصفحة مع تغييرات معلّقة (`beforeunload`)، وتُفرَّغ المعلّقة عند مغادرة الصفحة أو إخفائها.

## قرارات تصميم وبدائلها

| القرار | البديل المرفوض | السبب |
|---|---|---|
| SQLite | PostgreSQL منذ البداية | لا حاجة لخدمة منفصلة لحِمل صغير؛ نسخ احتياطي بملف؛ الانتقال لاحقًا ممكن |
| جلسات بكوكي في القاعدة | JWT | إبطال فوري (تعطيل/تغيير كلمة مرور/خروج من كل الأجهزة) وبلا أسرار توقيع تُدار |
| رأس CSRF مخصص + Origin | رموز CSRF لكل نموذج | أبسط وأمتن مع SPA؛ المتصفح لا يضيف رؤوسًا مخصصة عبر المواقع |
| Chromium للـPDF | مكتبة PDF بحتة (pdfkit…) | الحروف العربية المتصلة وRTL والجداول المعقدة تُرسم صحيحة في المتصفح، وتتطابق مع معاينة HTML |

| حزمة واحدة (npm package) | monorepo بحزم متعددة | بساطة التشغيل والنشر؛ الحدود مفروضة بـESLint |
| بلا حالة عامة للواجهة (Redux…) | — | بيانات الخادم في TanStack Query، والباقي حالة محلية |
