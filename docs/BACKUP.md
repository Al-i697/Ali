# النسخ الاحتياطي والاستعادة والتعافي

> بيانات المعلم سنة دراسية كاملة من الجهد. القاعدة: **نسخة واحدة على نفس القرص ليست نسخة احتياطية.**

## ما الذي يُنسخ

ملف قاعدة البيانات كاملًا (كل المستخدمين وكل بياناتهم + الجلسات + سجل العمليات) في ملف واحد متّسق. لا شيء آخر مطلوب: الإعدادات المحفوظة في الحساب (المظهر، المستويات، أوقات الحصص…) داخل القاعدة نفسها. ما **ليس** فيها: ملف `.env` (احفظه أنت، وفيه `BACKUP_PASSPHRASE`).

## أنواع النسخ

| النوع | متى | الاحتفاظ |
|---|---|---|
| **تلقائية** (`auto`) | كل `BACKUP_INTERVAL_HOURS` (24 افتراضيًا)، أول نسخة بعد 15 ثانية من التشغيل إن لزم | آخر `BACKUP_KEEP` (14) |
| **يدوية** (`manual`) | بزر «نسخة احتياطية الآن» أو `cli backup` | **لا تُحذف تلقائيًا** |
| **قبل الترقية** (`pre-migration`) | تلقائيًا قبل تطبيق هجرة على بيانات موجودة | آخر 5 |
| **قبل الاستعادة** (`pre-restore`) | تلقائيًا قبل أي استعادة — لتتراجع إن كانت النسخة الخطأ | آخر 5 |

اسم الملف: `sijilli-YYYYMMDD-HHMMSS-mmm-<النوع>.sqlite` (والمشفّرة تنتهي بـ`.enc`)، والتوقيت UTC.

## كيف تُؤخذ النسخة (للمطوّر)

1. واجهة `backup()` في SQLite تنسخ قاعدة حيّة بشكل **متّسق** (لا حاجة لإيقاف الخادم، ولا تُلتقط معاملة نصف مكتملة).
2. يُفتح الملف الناتج ويُجرى `PRAGMA integrity_check` — **نسخة تالفة تُرفض ولا تُعتمد** (النسخة التالفة أخطر من غيابها).
3. إن وُجدت `BACKUP_PASSPHRASE` يُشفَّر الملف ثم يُحذف الأصل غير المشفّر.
4. صلاحيات الملف `600` والمجلد `700`.
5. تُدوَّر النسخ القديمة حسب الجدول أعلاه.

## التشفير

- **AES-256-GCM** بمفتاح مشتق من العبارة عبر **scrypt** (N=2¹⁵) وملح عشوائي لكل ملف؛ وسم المصادقة يكشف أي تلاعب بالملف.
- الصيغة: `"SJLBK1" | salt(16) | iv(12) | ciphertext | tag(16)`.
- ⚠️ **إن ضاعت العبارة ضاعت النسخ المشفّرة نهائيًا — لا توجد طريقة لاسترجاعها.** احفظ العبارة في مدير كلمات مرور أو خزنة، **منفصلة** عن النسخ.
- لفك تشفير نسخة يدويًا: `BACKUP_PASSPHRASE=… node dist/server/cli.js decrypt-backup <ملف.enc> <خروج.sqlite>`.
- تغيير العبارة لا يعيد تشفير النسخ القديمة: تبقى قابلة للاستعادة بالعبارة التي شُفّرت بها.

## الاستعادة

### من الواجهة (للمدير): الإعدادات ← النسخ الاحتياطي

- زر **الاستعادة** بجانب أي نسخة، أو «استعادة من ملف» لرفع ملف من جهازك.
- يُطلب كتابة كلمة «استعادة» للتأكيد (استبدال **كل** بيانات النظام).
- قبل الاستبدال تُؤخذ تلقائيًا نسخة `pre-restore`.
- بعدها يُعاد تحميل التطبيق؛ وإن لم تكن جلستك ضمن النسخة المستعادة ستُطلب منك تسجيل الدخول.

### من سطر الأوامر (الأضمن للكوارث)

```bash
sudo systemctl stop sijilli          # أوقف الخادم أولًا
node dist/server/cli.js restore /path/to/sijilli-….sqlite --yes
sudo systemctl start sijilli
```

### فحوص الأمان أثناء الاستعادة

يُرفض الملف إن: لم يكن SQLite صالحًا · فشل `integrity_check` · لم يكن من «سجلي» (جداول ناقصة) · كان من **إصدار أحدث** من التطبيق (حدّث التطبيق أولًا) · كان مشفّرًا والعبارة غير مضبوطة أو خاطئة. نسخة قديمة من إصدار سابق تُقبل وتُرقَّى هجراتها تلقائيًا بعد الاستعادة.

## خطة نسخ خارج الخادم (3-2-1)

الحد الأدنى المعقول لمدرسة: **3 نسخ، على وسيطين، واحدة خارج الموقع.**

1. **على الخادم:** النسخ التلقائية (التطبيق يتولاها).
2. **على جهاز/قرص آخر:** تنزيل يدوي أسبوعيًا من الواجهة، أو أتمتة:
   ```bash
   # cron على جهاز آخر (مثال: يوميًا 3 صباحًا) — يسحب آخر نسخة عبر SSH
   0 3 * * * rsync -a --include='*auto.sqlite*' --exclude='*' sijilli@server:/var/lib/sijilli/backups/ /mnt/backup/sijilli/
   ```
3. **خارج الموقع:** خدمة تخزين سحابية مشفّرة (مع `BACKUP_PASSPHRASE` تكون الملفات مشفّرة قبل خروجها) أو قرص يُحفظ في مكان آخر.

## اختبار الاستعادة

نسخة لم تُجرَّب استعادتها ليست مضمونة. **مرة كل فصل دراسي على الأقل:**

1. على جهاز آخر (أو مجلد بيانات مؤقت): `DATA_DIR=/tmp/restore-test node dist/server/cli.js restore <نسخة> --yes`
2. `DATA_DIR=/tmp/restore-test node dist/server/cli.js check` — يطبع نتيجة `integrity_check` وعدّ السجلات (مستخدمون، طلاب، درجات…). قارنها بالتوقعات.
3. شغّل الخادم عليها (`DATA_DIR=/tmp/restore-test PORT=3999 node dist/server/index.js`) وادخل وراجع شعبة.

اختبار `npm run test:e2e` يتضمن استعادة فعلية عبر الواجهة، لكنه يختبر البرنامج لا نسخك أنت.

## خطة التعافي من الكوارث

| السيناريو | الإجراء |
|---|---|
| حذف بالخطأ (شعبة/طالب/درجات) | استعد آخر نسخة **على جهاز/مجلد منفصل** (انظر «اختبار الاستعادة»)، واستخرج ما تحتاجه يدويًا، أو استعدها كاملة إن كان الفقد كبيرًا (تفقد ما بعدها) |
| تلف قاعدة البيانات | أوقف الخادم، `cli check`؛ إن فشل فاستعد آخر نسخة سليمة |
| ترقية فاشلة | أوقف الخادم، استعد `pre-migration` الأحدث، وارجع للإصدار السابق من الشيفرة |
| فقدان الخادم/القرص | ثبّت التطبيق على خادم جديد، ضع `.env` (بنفس `BACKUP_PASSPHRASE`)، `cli restore` من آخر نسخة خارجية |
| استعادة بالخطأ | استعد نسخة `pre-restore` التي أُخذت قبلها |

## حق المحو وسياسة الاحتفاظ

حذف حساب (من المدير) يحذف بياناته من القاعدة الحيّة فقط. **النسخ الاحتياطية السابقة تحتفظ بنسخة قديمة** حتى تُحذف أو تُدوَّر. إن كان القانون أو سياسة المدرسة يستلزم محوًا كاملًا فاحذف النسخ المعنية يدويًا (الواجهة أو الملفات) بعد حذف الحساب.
