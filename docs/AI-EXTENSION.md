# نقطة توسعة المساعد الذكي

> **الحالة: تصميم وعقد برمجي فقط.** لا يوجد في هذه النسخة أي مزوّد ذكاء اصطناعي ولا أي زر أو ميزة ظاهرة في الواجهة. الغرض أن تكون الإضافة مستقبلًا **آمنة ومحدودة** دون إعادة بناء.

## ما الموجود فعلًا

| المكوّن | الملف | الوظيفة |
|---|---|---|
| العقد | `src/server/ai/provider.ts` | واجهة `AiProvider` وخدمة `AiService` (تسجيل مزوّد، فحص الجاهزية، تشغيل مهمة بحدود مدخلات) |
| التركيب | `src/server/app.ts` | `app.ai` (مُنشأة بلا مزوّد) |
| الإعلان | `GET /api/system/info` | `capabilities.ai` = `false` حتى يُسجَّل مزوّد جاهز |
| الاختبار | `tests/server/core.test.ts` | بلا مزوّد ← `501 AI_UNAVAILABLE`؛ ومع مزوّد تجريبي تعمل الحدود |

المهام المتوقعة (`AiTask`): `lesson-draft` (مسودة تحضير من العنوان والأهداف) · `assessment-ideas` (أفكار تقويم) · `support-plan-ideas` (أفكار علاج/إثراء).

## ضوابط إلزامية لأي مزوّد

هذه الضوابط جزء من التصميم، لا اقتراحات:

1. **بيانات الطلاب لا تغادر الخادم.** يُمرَّر للمزوّد **نص اختاره المعلم صراحةً** (عنوان درس، أهداف، وصف) — **لا أسماء طلاب، لا درجات، لا ملاحظات سلوكية، لا أرقام**. أي بناء لمدخل المزوّد يجب أن يمرّ بدالة تنقية موثّقة ومُختبَرة.
2. **المعلم يقرّر ويراجع:** ناتج المزوّد **مقترح** يُعرض للمراجعة والتعديل ولا يُحفظ تلقائيًا ولا يُرصد منه شيء في الدرجات أبدًا.
3. **تفعيل صريح:** يُفعَّل بمتغير بيئة على الخادم (مفتاح/عنوان نموذج) وبموافقة المدير، ويبقى معطّلًا افتراضيًا. الواجهة تُظهر الميزة **فقط** إن كان `capabilities.ai === true`.
4. **الشفافية:** يظهر في الواجهة مصدر الاقتراح («مقترح من مساعد آلي — راجعه»)، ويُسجَّل في `audit_log` نوع المهمة واسم المزوّد وطول المدخل (**لا نصه**).
5. **حدود:** طول المدخل ≤ 4000 حرف (مُطبَّق)، وتحديد معدل خاص بالمسار، ومهلة للطلب الخارجي.
6. **تفضيل النماذج المحلية:** إن كانت سياسة المدرسة تمنع الإرسال لخدمة خارجية فاستعمل نموذجًا محليًا (يعمل على الخادم نفسه) خلف نفس الواجهة.
7. **الإخفاق آمن:** تعذّر المزوّد لا يؤثر على أي وظيفة أخرى؛ يظهر خطأ عربي واضح فقط.

## كيف تضيف مزوّدًا (خطوات)

1. **نفّذ الواجهة** في ملف جديد `src/server/ai/<اسم>.ts`:
   ```ts
   import type { AiProvider } from './provider';

   export function createMyProvider(cfg: { endpoint: string; apiKey?: string }): AiProvider {
     return {
       id: 'my-provider',
       isAvailable: () => Boolean(cfg.endpoint),
       async complete({ task, input }) {
         // 1) ابنِ الطلب من `task` و`input` (نص المعلم فقط، منقّى)
         // 2) استدعِ النموذج بمهلة (AbortSignal.timeout)
         // 3) أعد { text, provider: 'my-provider' }
       },
     };
   }
   ```
2. **أضف إعداداتها** إلى `config.ts` (متغيرات بيئة اختيارية بـZod) و`.env.example`.
3. **سجّلها** في `buildApp` عند وجود الإعداد: `app.ai.register(createMyProvider(...))`.
4. **أضف مسارًا** في وحدة جديدة (انظر [ADDING-A-MODULE](ADDING-A-MODULE.md)): `POST /api/ai/run` بمخطط Zod (`task` من القائمة، `input` ≤ 4000) يستدعي `app.ai.run(...)` ويسجّل `audit` بلا نص.
5. **الواجهة:** زر «اقتراح» في محرر التحضير يظهر فقط إن كان `system.capabilities.ai`، ويضع الناتج في حقل قابل للتعديل مع وسم «مقترح آلي».
6. **اختبارات:** (أ) بلا مزوّد ← 501 والواجهة لا تعرض الزر، (ب) مدخل منقّى لا يحوي أسماء، (ج) المهلة والأخطاء لا تُسقط الخادم، (د) E2E يتأكد من عدم ظهور الزر عند التعطيل.

## ما لا يُنفَّذ بالذكاء الاصطناعي (قرار تصميم)

رصد الدرجات، تحديد مستوى الطالب، ملاحظات سلوكية عن طالب بعينه، أي قرار تربوي أو إداري. هذه مسؤولية المعلم، والنظام يقدّم أدوات وليس أحكامًا.
