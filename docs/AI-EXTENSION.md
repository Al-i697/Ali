# المساعد الذكي

> **الحالة: مُنفَّذ بمزوّد واحد (Claude عبر الـSDK الرسمي)، ومعطّل افتراضيًا.** لا يظهر شيء للمعلمين حتى يجتمع شرطان: مزوّد مضبوط في بيئة الخادم **و**موافقة صريحة من المدير. لا يوجد بعدُ مزوّد لنموذج محلي (الواجهة جاهزة لإضافته — انظر [إضافة مزوّد](#إضافة-مزوّد-جديد)).
>
> ⚠️ **ما اختُبر وما لم يُختبر:** كل الاختبارات الآلية (وحدات وتكامل وE2E في متصفح حقيقي) تعمل على **خادم Claude وهمي محلي** يحاكي واجهة Messages. **لم تُجرَّب الميزة على واجهة Anthropic الحقيقية** (لا مفتاح في بيئة التطوير). قبل التفعيل للمعلمين نفّذ على الخادم الفعلي: `npm run cli -- ai-check` (أو `node dist/server/cli.js ai-check`) — طلب صغير بلا بيانات حقيقية يتحقق من المفتاح والنموذج والوصول والرد المنظَّم.

## ما الذي يفعله

ثلاث مهام يطلبها المعلم من داخل شاشاته، وتعيد **مسودات** يراجعها ويختار ما يُدرَج منها:

| المهمة | أين تظهر | ما يعيده المساعد |
|---|---|---|
| `lesson-draft` — مسودة تحضير | محرر التحضير ← بطاقة «المساعد الذكي» ← «اقترح مسودة التحضير» | نواتج وأهداف ومفاهيم واستراتيجيات ومصادر وسير الحصة بأزمنتها وأساليب تقويم وواجب وفكرتا معالجة وإثراء |
| `assessment-ideas` — أفكار تقويم | محرر التحضير ← «أفكار للتقويم» | 3–5 أفكار بنوعها ووصفها ومعايير نجاحها |
| `support-plan-ideas` — أفكار خطة علاجية/إثرائية | نافذة «خطة جديدة» ← «اقترح أفكارًا بالمساعد الذكي» | أسباب محتملة عامة وهدف قابل للقياس وإجراءات |

## كيف يعمل (من الضغطة إلى الحفظ)

```
المعلم يكتب العنوان/الأهداف/الملاحظات (مُعبَّأة من تحضيره) ويضغط «اقترح»
   │  POST /api/ai/run  { task, title, objectives, notes, minutes?, assignmentId?, acknowledgeNames? }
   ▼
الخادم (modules/ai/service.ts → runAi)
   1) المزوّد مضبوط؟            لا ← 501 AI_UNAVAILABLE
   2) المدير وافق؟              لا ← 501 AI_NOT_APPROVED
   3) الحصة اليومية للمعلم؟     مستنفدة ← 429 AI_DAILY_LIMIT
   4) المقرر مملوك للمعلم؟ (للصف واسم المادة فقط)     غير مملوك ← 404
   5) تنقية النص (محارف تحكم/اتجاه، < >)  ثم الطول الكلي ≤ 4000     أطول ← 400 AI_INPUT_TOO_LONG
   6) بريد/هاتف/رقم ≥ 8 خانات؟  نعم ← 400 AI_INPUT_REJECTED  (يُسجَّل السبب فقط)
   7) يطابق اسم أحد طلابه؟      نعم ← 422 AI_NAME_CONFIRM_REQUIRED  ما لم يؤكد المعلم (acknowledgeNames) فيُسجَّل التأكيد
   8) حد الدقيقة والتزامن (AiService)   تجاوز ← 429 AI_RATE_LIMITED / AI_BUSY
   9) بناء الرسالة (tasks.ts): الحقول بين وسوم + الصف والمادة فقط ← المزوّد (SDK رسمي، مخرجات منظَّمة)
  10) فحص الرد: رفض/قطع/بنية خاطئة ← أخطاء عربية  ثم تنظيفه (تنسيق، أطوال، قيم خارج القوائم)
   ▼
الواجهة: خطوة «مراجعة» بوسم «مقترح من مساعد آلي — راجعه» ← المعلم يختار الأقسام ← «إدراج المحدد»
   ▼
الدمج إضافة فقط (merge.ts) في مسودة المعلم ← الحفظ التلقائي المعتاد (لا مسار حفظ خاص بالمساعد)
```

## التفعيل خطوة بخطوة

1. **اضبط بيئة الخادم** (`.env` أو متغيرات الخدمة):
   ```
   AI_PROVIDER=anthropic
   ANTHROPIC_API_KEY=sk-ant-...        # سرّ: لا يُسجَّل ولا يُعرض في أي واجهة
   # AI_MODEL=claude-opus-5-5          # اختياري (انظر «النموذج والكلفة»)
   ```
2. أعد تشغيل الخادم. إن كان `AI_PROVIDER=anthropic` بلا مفتاح يرفض الخادم البدء برسالة واضحة.
3. **تحقق من الاتصال:** `npm run cli -- ai-check` ← يطبع المزوّد والنموذج والزمن والرموز، أو سبب الفشل (مفتاح مرفوض، نموذج غير متاح، شبكة، مهلة…) ورمز الخروج `1`.
4. **وافق من الواجهة (مدير):** الإعدادات ← «المساعد الذكي» ← تفعيل المساعد للمعلمين (تأكيد يذكر ما يُرسَل وإلى أين). الإيقاف فوري وبلا تأكيد.
5. المعلمون يرون الأدوات بعد تحديث الصفحة (قدرة `capabilities.ai` تُقرأ عند فتح التطبيق).

> الترقية من نسخة سابقة **لا تفعّل** المساعد: الهجرة `0003_app_settings` تضيف جدولًا فارغًا فقط (مغطّى في `tests/server/upgrade.test.ts`).

## متغيرات البيئة

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `AI_PROVIDER` | `none` | `none` (معطّل) أو `anthropic` |
| `ANTHROPIC_API_KEY` | — | مفتاح الخدمة. مطلوب عند `anthropic` |
| `AI_BASE_URL` | الخدمة الرسمية | عنوان بديل (بوابة/وكيل مؤسسي). يظهر مضيفه للمعلم والمدير كوجهة للنص؛ يُعدّ «شبكة محلية» إن كان `localhost`/`127.*` |
| `AI_MODEL` | `claude-opus-5-5` | معرّف النموذج. انظر «النموذج والكلفة» |
| `AI_EFFORT` | `low` | عمق التفكير: `low` \| `medium` \| `high` (أسرع وأرخص ← أعمق) |
| `AI_TIMEOUT_MS` | `90000` | مهلة **المحاولة الواحدة** (5000–300000). قد تُعاد المحاولة مرة (أخطاء الشبكة/الازدحام)، فأقصى انتظار ≈ ضعف المهلة |
| `AI_DAILY_LIMIT` | `30` | طلبات ناجحة لكل معلم خلال آخر 24 ساعة |
| `AI_RATE_PER_MINUTE` | `6` | طلبات لكل معلم في الدقيقة |
| `AI_MAX_CONCURRENCY` | `3` | طلبات متزامنة للخادم كله |

**خلف وكيل عكسي:** يجب أن تتجاوز مهلة القراءة أقصى انتظار (الافتراضي ≈ 190 ثانية)، وإلا قطع الوكيل الطلب قبل رد المزوّد. في Nginx: `location /api/ai/ { proxy_read_timeout 240s; proxy_pass http://127.0.0.1:3000; … }`. ويلزم أن يصل الخادم إلى مضيف المزوّد عبر HTTPS (جدار ناري صادر).

### النموذج والكلفة

- الافتراضي `claude-opus-5-5` أعلى جودة لكنه الأغلى والأبطأ. مسودات التحضير لا تحتاج غالبًا هذا المستوى: جرّب نموذجًا أصغر (مثل `claude-sonnet-5-5` أو `claude-haiku-5-5`) بـ`ai-check` ثم بنظرة المعلمين لجودة المسودات. **القرار لك؛ لا يُخفَّض النموذج تلقائيًا.**
- الاستهلاك محدود بحدّي اليوم والدقيقة والتزامن أعلاه، ويُعرض للمدير مجمَّعًا (طلبات ورموز دخل/خرج) في تبويب «المساعد الذكي».
- الرجوع التلقائي عند رفض مصنّفات السلامة طلبًا مشروعًا (`fallbacks: "default"` ببيتا `server-side-fallback-2026-07-01`) **مفعّل افتراضيًا** لنماذج Opus/Sonnet، ولا يُرسَل لنماذج Haiku. إن رفضه حسابك أو بوابتك (400) يُعاد الطلب بدونه تلقائيًا ويُتذكَّر ذلك.
- يُرسَل `output_config.effort` ولا تُرسَل معاملات أخذ العينات (`temperature`…) لأن بعض النماذج الحالية ترفضها.

## حدود معروفة (بصراحة)

1. **الاسم المفرد لا يُلتقط.** «أحمد» وحده يلتبس بكلمات الدروس، فلا يُعدّ مطابقة. الحماية تقوم على: ما يظهر للمعلم في الحقول قبل الإرسال، وتنبيه ثابت «لا تكتب أسماء طلاب»، ومطابقة الأسماء المركّبة.
2. **ما يُرسَل لمزوّد خارجي يخرج من خادمك** ويخضع لشروط مزوّده في الاحتفاظ والمعالجة. التصميم يُبقي الإرسال محصورًا في نصوص تعليمية عامة، لكن **سياسة المدرسة** هي التي تقرر السماح بالمزوّد الخارجي أم لا.
3. **المحتوى قد يخطئ علميًا أو منهجيًا.** الواجهة تنبّه المعلم للمراجعة؛ لا نتحقق من صحة المحتوى.
4. **إلغاء الطلب من الواجهة لا يسحبه:** يستمر عند المزوّد ويُحتسب من الحصة؛ تُتجاهل نتيجته فقط.
5. **لا مزوّد محلي بعد.** الإرسال إلى نموذج على شبكتك يحتاج مزوّدًا جديدًا خلف نفس الواجهة (أدناه). وإلى ذلك الحين فالمزوّد الوحيد خدمة سحابية.
6. **لم يُجرَّب على الخدمة الحقيقية** (انظر التنبيه أعلاه): السلوك مبنيّ على وثائق الواجهة وعلى خادم وهمي يحاكيها، وقد تظهر فروق دقيقة عند أول تشغيل فعلي (مثل دعم النموذج المختار لمعامل ما)؛ `ai-check` هو أول فحص.

## الأعطال ورسائلها

| الرمز | الحالة | متى |
|---|---|---|
| `AI_UNAVAILABLE` / `AI_NOT_APPROVED` | 501 | لا مزوّد مضبوط / لم يوافق المدير |
| `AI_DAILY_LIMIT` / `AI_RATE_LIMITED` / `AI_BUSY` | 429 | الحصة اليومية / حد الدقيقة / تزامن الخادم |
| `AI_INPUT_TOO_LONG` / `AI_INPUT_REJECTED` | 400 | تجاوز الطول / بيانات اتصال |
| `AI_NAME_CONFIRM_REQUIRED` | 422 | النص يطابق اسم طالب |
| `AI_REFUSED` | 422 | رفض المزوّد (مصنّفات السلامة) رغم الرجوع التلقائي |
| `AI_PROVIDER_AUTH` / `AI_PROVIDER_REJECTED` | 424 | المفتاح مرفوض / الطلب أو النموذج مرفوض |
| `AI_PROVIDER_BUSY` | 429 | حدّ حساب المزوّد |
| `AI_TIMEOUT` / `AI_NETWORK` / `AI_TRUNCATED` / `AI_INVALID_OUTPUT` / `AI_PROVIDER_ERROR` | 424 | مهلة / شبكة / رد مقطوع / بنية غير صالحة / خطأ عام |
| `AI_NOT_CONFIGURED` | 409 | المدير حاول التفعيل بلا مزوّد مضبوط |

رسائل المعلم عامة ولطيفة؛ أما المدير فيرى في تبويب «المساعد الذكي» **آخر خطأ** (نوعه وحالته HTTP ووقته) وسجل الخادم يحمل `request-id` لدى المزوّد لتتبّع المشكلة معه.

## إضافة مزوّد جديد

الواجهة التي يلتزم بها أي مزوّد (`src/server/ai/provider.ts`):

```ts
interface AiProvider {
  id: string; label: string; model: string;
  host: string;     // يظهر للمعلم والمدير كوجهة للنص
  local: boolean;   // true إن بقي النص على شبكتك (لا يخرج للإنترنت)
  isAvailable(): boolean;
  complete<T>(req: { system: string; user: string; schema: ZodType<T> }): Promise<{ data: T; model: string; usage: { inputTokens: number; outputTokens: number } }>;
}
```

1. **نفّذ المزوّد** في `src/server/ai/<اسم>.ts`: يستقبل تعليمات النظام ورسالة المعلم وبنية الرد (Zod) ويعيد الرد **المتحقَّق منه**؛ أخطاؤه من نوع `AiError` بأنواعها المحددة (`auth`، `timeout`، `network`، `refused`…) وبلا أي نص مُدخَل أو مفتاح في الرسائل.
2. **أضف إعداداته** إلى `config.ts` (قيمة جديدة في `AI_PROVIDER`) و`.env.example`.
3. **سجّله** في `buildApp` (`app.ts`) عند وجود الإعداد: `ai.register(createMyProvider(...))`.
4. **اختبره** على خادم وهمي كما في `tests/server/ai-anthropic.test.ts`: شكل الطلب، الأخطاء (401/429/5xx/مهلة/شبكة)، وألّا يتسرب مفتاح.
5. لا تغيير مطلوب في الواجهة: تقرأ المزوّد من `/api/ai/status`.

## إضافة مهمة جديدة

1. ثابت جديد في `AI_TASK` وحالة في `aiRunSchema` (`src/shared/schemas/ai.ts`) ونوع النتيجة في `AiRunResponse` (`dto.ts`).
2. في `tasks.ts`: بنية الرد (متساهلة)، دالة التنظيف `finishX`، وحالة في `planTask` تبني الرسالة **من حقول المعلم فقط** بين وسوم.
3. في `modules/ai/service.ts`: أضف الحقول النصية للمهمة إلى `cleanInput` و`textsOf` (فتمرّ بالتنقية وفحص الاتصال والأسماء تلقائيًا).
4. الواجهة: نافذة جديدة فوق `AiAssistShell` (إدخال ← مراجعة) ودالة دمج **إضافية فقط** في `merge.ts`، مع اختبار يثبت أنها لا تستبدل نص المعلم.
5. اختبارات: تنقية/تنظيف (`ai-sanitize`)، مسار `/ai/run` (`ai.test.ts`)، ومرحلة `ai` في E2E.

## ما لا يُنفَّذ بالذكاء الاصطناعي (قرار تصميم)

رصد الدرجات، تحديد مستوى الطالب، ملاحظات سلوكية عن طالب بعينه، أي قرار تربوي أو إداري. هذه مسؤولية المعلم، والنظام يقدّم أدوات وليس أحكامًا. لهذا لا يصل المساعد إلى أي بيانات طلاب أصلًا.
