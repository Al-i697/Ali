# خارطة الطريق والحالة

آخر تحديث مع النسخة 0.1.0. الجدول يفرّق **بصراحة** بين المُنجز والمُختبَر وما لم يُبدأ.

## المُنجز (MVP)

| الوحدة | التنفيذ | الاختبار |
|---|---|---|
| لوحة التحكم | ✅ | تكامل + E2E + مسح بصري |
| الأعوام والفصول والمواد | ✅ | تكامل + E2E |
| الشعب والطلاب (إضافة/استيراد/نقل/ترقية/بحث) | ✅ | تكامل (بما فيه الاستيراد من CSV/Excel) + E2E |
| التحضير الإلكتروني (حفظ تلقائي، قوالب، نسخ) | ✅ | تكامل + E2E |
| الجدول الأسبوعي | ✅ | تكامل + مسح بصري |
| التقويم المستمر (شبكة الدرجات) | ✅ | وحدات حساب + تكامل + E2E تفاعلي (كيبورد/لصق/أرقام هندية) |
| ملف الطالب | ✅ | تكامل + مسح بصري |
| التقارير (5 أنواع × PDF/Excel/HTML) | ✅ | تكامل + E2E (تنزيل حقيقي) + فحص بصري يدوي للصفحات |
| المهام والتقويم الدراسي | ✅ | تكامل + E2E |
| المستخدمون والأدوار والجلسات | ✅ | تكامل + مصفوفة صلاحيات + E2E |
| النسخ الاحتياطي والاستعادة والتشفير | ✅ | تكامل + E2E (استعادة فعلية عبر الواجهة) + بروفة CLI |
| الحساب التجريبي | ✅ | يُستعمل في E2E |

## غير مُنفَّذ بعد (بصراحة)

| البند | ملاحظة |
|---|---|
| **سجل المختبر والأنشطة** | مطلوب في المتطلبات الأصلية؛ لم يُبدأ |
| **الخطط العلاجية والإثرائية الفردية** | موجود جزئيًا: حقول المعالجة/الإثراء في التحضير وقوائم الطلاب المستهدفين في تحليل الشعبة. لا وحدة خطط فردية بمتابعة وحالة |
| **المساعد الذكي** | عقد برمجي معطّل فقط ([AI-EXTENSION](AI-EXTENSION.md)) |
| الحضور والغياب اليومي | خارج المتطلبات الأصلية؛ الغياب مدعوم داخل رصد التقويم فقط |
| المصادقة الثنائية (2FA) | غير منفَّذة |
| استعادة كلمة المرور بالبريد | غير منفَّذة عمدًا (لا خدمة بريد) — المدير يعيّن مؤقتة |
| تصدير/استيراد بيانات معلم واحد | خارج النسخ الاحتياطي الكامل |
| تعدد المدارس/المؤسسات (hierarchy) | كل معلم حساب مستقل؛ لا مدير مدرسة يرى تقارير معلميه |
| تطبيق جوال أصلي / PWA غير متصلة | الواجهة تعمل على المتصفح؛ لا وضع عدم اتصال |
| اختبار على Safari/Firefox وأجهزة فعلية | اختُبر على Chromium فقط |
| بناء صورة Docker | الملفات مكتوبة ولم تُبنَ في بيئة التطوير |

## الأولويات المقترحة للمراحل التالية

1. **سجل المختبر/الأنشطة** — وحدة مستقلة بجدول وصفحة (اتّبع [ADDING-A-MODULE](ADDING-A-MODULE.md)).
2. **الخطط العلاجية الفردية** — خطة لكل طالب (هدف، إجراءات، تاريخ، متابعة، نتيجة) مرتبطة بقوائم التحليل الموجودة، وتقرير خاص.
3. **2FA (TOTP)** للمدير على الأقل، وقفل الدخول حسب عنوان IP إضافة للحساب.
4. **تصدير بيانات معلم** كاملًا (ZIP: Excel + PDF لكل شعبة) ونقلها لحساب آخر.
5. **دور «مدير مدرسة»** بصلاحية قراءة تقارير معلميه المجمَّعة (بموافقتهم).
6. **PWA** (تثبيت على الجوال + نسخة مقروءة دون اتصال للجدول والقوائم).
7. المساعد الذكي بالضوابط الموثّقة، وبنموذج محلي أولًا.
8. الانتقال إلى PostgreSQL إن تجاوز الاستخدام مدرسة واحدة.

## ديون تقنية معلومة

- الهجرة واحدة (`0000_init.sql`) لأن المشروع لم يُنشر؛ بعد أول نشر تصبح كل التغييرات هجرات إضافية.
- حزمة الواجهة الرئيسية ~410 ك.ب (127 ك.ب مضغوطة) + حزمة مكوّنات ~250 ك.ب؛ كافية، ويمكن تقسيمها أكثر.
- الخطوط تُضمَّن بصيغتي woff2 وwoff في البناء؛ يمكن إسقاط woff لتقليل الحجم.
- فحوص إمكانية الوصول المؤتمتة بسيطة (أسماء العناصر التفاعلية)؛ لا تدقيق شامل بقارئ شاشة.
