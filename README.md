# سجلي — السجل الإلكتروني للمعلم

بديل رقمي للسجل المصاحب الورقي للمعلم في سلطنة عُمان: تحضير الدروس، رصد التقويم المستمر، ملف الطالب، والتقارير — بواجهة عربية كاملة (RTL) تعمل على الحاسوب والجوال والآيباد، وقاعدة بيانات حقيقية، وحساب مستقل لكل معلم.

> **حالة المشروع:** نسخة أولية عاملة (MVP) تشمل لوحة التحكم، الأعوام والشعب والطلاب، التحضير الإلكتروني، التقويم المستمر، الخطط العلاجية والإثرائية، سجل المختبر والأنشطة، التقارير، المهام، وإدارة المستخدمين والنسخ الاحتياطي. الوحدات التي **لم** تُنفَّذ بعد مذكورة بصراحة في [الجدول أدناه](#ما-المُنجز-وما-غير-المُنجز) وفي [خارطة الطريق](docs/ROADMAP.md) — لا شيء في الواجهة يتظاهر بأنه يعمل وهو لا يعمل.

## ما المُنجز وما غير المُنجز

| الوحدة | الحالة | التفاصيل |
|---|---|---|
| لوحة التحكم | ✅ | حصص اليوم وحالة تحضيرها، سجلات الدرجات الناقصة، المهام القريبة، تحضير الأسبوع، وقائمة «ابدأ» للمستخدم الجديد |
| الأعوام والفصول والمواد | ✅ | عام بفصلين تلقائيًا، فصل «حالي» يُحسب من التواريخ، نسخ بنية عام سابق، مواد بألوان |
| الشعب والطلاب | ✅ | إضافة سريعة بـ Enter، لصق أسماء، استيراد Excel/CSV، نقل وترقية بين الشعب والأعوام، بحث عربي ذكي (همزات/تشكيل/أرقام) |
| التحضير الإلكتروني | ✅ | نواتج وأهداف ومفاهيم واستراتيجيات ومصادر وأنشطة بزمن وتقويم وواجب ومعالجة وإثراء، **حفظ تلقائي**، قوالب، **نسخ التحضير** لشعب/تواريخ أخرى، طباعة وPDF |
| الجدول الأسبوعي | ✅ | حصص الأسبوع (أيام العمل وأوقات الحصص قابلة للضبط) وربطها بالتحضير |
| التقويم المستمر | ✅ | شبكة درجات بالكيبورد وحفظ تلقائي ولصق من Excel، أنواع تقويم (كتابي/شفهي/عملي/مشروع/واجب)، درجة أو إتقان (1–4)، مهارات مرتبطة، مجموع ونسبة ومستوى لحظيًا |
| ملف الطالب | ✅ | الأداء بالمواد، المهارات، الملاحظات (سلوكية/أكاديمية…)، البيانات، تقرير فردي PDF |
| التقارير | ✅ | 7 تقارير: كشف درجات الشعبة، تحليل الأداء، تقرير الطالب، سجل التحضير، ورقة تحضير الدرس، الخطط العلاجية والإثرائية، سجل المختبر والأنشطة — بصيغ **PDF وExcel وطباعة** |
| المهام والتقويم الدراسي | ✅ | مهام ومواعيد واختبارات، تقويم شهري يجمع المهام والتقويمات والتحضير |
| المستخدمون والأمان | ✅ | حسابات مستقلة وعزل كامل للبيانات، أدوار (مدير/معلم)، كلمات مرور مؤقتة، جلسات وأجهزة، سجل عمليات |
| النسخ الاحتياطي | ✅ | تلقائي + يدوي + تنزيل + **استعادة** (من الخادم أو من ملف)، تشفير اختياري AES-256 |
| الخطط العلاجية والإثرائية | ✅ | خطة فردية لكل طالب (تشخيص، هدف، استراتيجيات، تاريخ بدء ومراجعة) بـ**خط أساس** لنسبته لحظة الإنشاء يُقارَن بنسبته الحالية لقياس الأثر؛ **اقتراحات تلقائية** من دفتر الدرجات (دون حد العلاج/فوق حد الإثراء) وإنشاء جماعي بنقرتين؛ سجل متابعة مؤرَّخ؛ إنجاز/إلغاء بنتيجة؛ تقرير PDF/Excel (قائمة أو خطة فردية)؛ وتكامل مع لوحة التحكم والتقويم الدراسي وملف الطالب |
| سجل المختبر والأنشطة | ✅ | تجارب وعروض وأنشطة ومشاريع وزيارات: **تخطيط قبل الحصة** (أهداف، مواد وأدوات، احتياطات سلامة، خطوات) ثم **تسجيل التنفيذ** بنقرتين (التاريخ الفعلي، عدد المشاركين بزر «كل طلاب الشعبة»، النتائج، التوصيات)؛ **نسخ ذكي** إلى الشعب الموازية باقتراح أقرب حصة فعلية من الجدول الأسبوعي؛ تنبيه بما **فات موعده** دون تسجيل؛ بحث عربي؛ لا يُقبل «نُفِّذ» لتاريخ لم يحن (في النموذج والخادم)؛ يبقى السجل عند حذف الشعبة؛ ورقة نشاط وسجل لفترة بـPDF/Excel؛ وتكامل مع لوحة التحكم والتقويم الدراسي |
| المساعد الذكي | ◐ نقطة توسعة فقط | عقد برمجي (`src/server/ai`) معطّل افتراضيًا ويعلن `capabilities.ai=false`؛ **لا ميزة ظاهرة للمستخدم**. انظر [AI-EXTENSION](docs/AI-EXTENSION.md) |
| الحضور والغياب اليومي | ❌ | غير منفَّذ (الغياب مدعوم داخل رصد التقويم فقط) |

## التشغيل السريع

المتطلبات: **Node.js ≥ 22.12**. تصدير PDF يتطلب Chromium (اختياري؛ بدونه تبقى «الطباعة» و«Excel» تعمل).

### 1) للتجربة والتطوير

```bash
npm install
npm run dev            # الخادم على :3000 والواجهة على http://127.0.0.1:5173
npm run cli -- seed-demo --email demo@sijilli.local --password "Demo-Teacher-2026"   # حساب تجريبي (اختياري)
```

أول زيارة تعرض صفحة **«الإعداد لأول مرة»** لإنشاء حساب المدير (وهو حسابك كمعلم أيضًا).

### 2) للإنتاج على خادم (بدون Docker)

```bash
npm ci
npm run build
cp .env.example .env   # عدّل DATA_DIR وAPP_URL…
NODE_ENV=production node dist/server/index.js   # أو: npm start
```

ضع خلف التطبيق وكيلًا عكسيًا بـ HTTPS (Caddy/Nginx) — انظر [DEPLOYMENT](docs/DEPLOYMENT.md) للتفاصيل الكاملة (متغيرات البيئة، systemd، الترقية، استكشاف الأخطاء).

### 3) Docker

```bash
docker compose up -d --build     # البيانات في volume باسم sijilli-data
```

> **أمانة:** ملفا `Dockerfile` و`docker-compose.yml` مكتوبان وفق أفضل الممارسات لكنهما **لم يُبنَيا** في بيئة التطوير التي أُنجز فيها المشروع (لا يوجد Docker daemon فيها). جرّبهما أولًا على بيئة غير حرجة.

## الحساب التجريبي

```bash
npm run cli -- seed-demo --email demo@sijilli.local --password "كلمة-قوية"
npm run cli -- purge-demo        # حذف كل الحسابات التجريبية وبياناتها
```

- الأسماء **وهمية بالكامل** (أسماء عُمانية شائعة مولَّدة عشوائيًا) وتعرض الواجهة لافتة دائمة: «حساب تجريبي: كل البيانات المعروضة وهمية».
- البيانات التجريبية مفصولة عن الحقيقية (حساب مستقل يُعلَّم `is_demo`) ويمكن حذفها بأمر واحد دون المساس بغيرها.
- يحوي 3 شعب (10/1 و10/2 و8/3 — نحو 72 طالبًا) بتقويمات ودرجات وتحضيرات ومهام وخطط علاجية وإثرائية وأنشطة مختبر (منفَّذة ومخطَّطة وواحد فات موعده) لتجربة كل الميزات.

## التقنيات والمعمارية

| الطبقة | التقنية |
|---|---|
| الخادم | Node 22 · Fastify 5 · TypeScript · Zod 4 (تحقق برسائل عربية) |
| قاعدة البيانات | **SQLite** (better-sqlite3، وضع WAL، `synchronous=FULL`) · Drizzle ORM · هجرات SQL مُرقَّمة |
| الواجهة | React 19 · Vite 8 · Tailwind 4 · TanStack Query · React Router 7 · Radix UI · React Hook Form |
| التقارير | HTML آمن ← PDF عبر Chromium بلا واجهة · Excel عبر ExcelJS |
| الاختبارات | Vitest (وحدات وتكامل) · Playwright-core (E2E في متصفح حقيقي) |

**لماذا SQLite؟** معلم واحد أو مدرسة صغيرة = حِمل كتابة صغير؛ SQLite تعطي أداءً ممتازًا، وتشغيلًا بلا خدمة قاعدة بيانات منفصلة، ونسخًا احتياطيًا بملف واحد. الطبقة معزولة (`src/server/db`) والاستعلامات عبر Drizzle، فالانتقال إلى PostgreSQL ممكن لاحقًا إن كبر الاستخدام — انظر [ARCHITECTURE](docs/ARCHITECTURE.md#قاعدة-البيانات).

```
src/
  shared/    عقود مشتركة بين الخادم والواجهة: مخططات Zod، الثوابت، حساب الدرجات، أنواع DTO
  server/    Fastify: modules/<وحدة>/{routes,service}.ts · db/ · lib/ · reports/ · cli/ · demo/ · ai/
  web/       React: features/<ميزة>/ · components/ui (مكوّنات النظام) · lib/ · styles/
tests/       server/ (تكامل) · shared/ (وحدات)
scripts/     e2e.mjs · build-server.mjs · gen-api-doc.ts
docs/        الوثائق
```

قواعد معمارية تُفرَض بالأدوات (ESLint `no-restricted-imports`): الواجهة لا تستورد من الخادم وعكسه، و`src/shared` لا يعتمد على Node.

## الاختبارات

**اختبارات الخادم والوحدات (Vitest — 166 اختبارًا):**
المصادقة والجلسات والقفل وCSRF، عزل بيانات المعلمين، الأعوام والشعب والطلاب والاستيراد، التحضير والنسخ، التقويم وحساب المجاميع، الخطط العلاجية (خط الأساس والاقتراحات والعزل)، سجل المختبر (الحارس الزمني والإحصاءات والبحث والنسخ الذرّي والعزل والحذف المتسلسل والتكامل)، التقارير بأنواعها، النسخ الاحتياطي والتشفير والاستعادة، **ترقية قاعدة بيانات قديمة بنسخة أمان تلقائية** و**استعادة نسخة احتياطية بمخطط أقدم وترقيتها بعد الاستعادة**، ومصفوفة صلاحيات تُولَّد من **كل** مسارات الـAPI (أي مسار جديد غير محمي يُفشل الاختبار).

**الاختبار الشامل `npm run test:e2e` (متصفح Chromium حقيقي، خادم مؤقت وقاعدة مؤقتة):**
- **رحلة معلّم جديد من الصفر:** إعداد النظام ← عام ← شعبة ← طلاب ← تحضير بحفظ تلقائي ← نسخ ← تقويم ← رصد درجة ← تقرير ← تنزيل PDF وExcel حقيقيين ← خروج.
- **الشبكة:** أرقام هندية، التنقل بالأسهم (مع RTL)، لصق من Excel، «غ»/«ع»، رفض القيم الخاطئة، الاستمرار بعد إعادة التحميل.
- **المدير:** إنشاء مستخدم بكلمة مؤقتة وإلزامه بتغييرها، التعطيل وإنهاء جلسته فورًا، الحذف النهائي بالتأكيد، **نسخ احتياطي واستعادة فعلية** عبر الواجهة، سجل العمليات.
- **الخطط العلاجية والمختبر:** إنشاء من النموذج والاقتراحات، التسجيل السريع، النسخ الذكي من الجدول (يُتحقَّق أن الموعد المقترح يوافق حصة فعلية)، حارس التاريخ المستقبلي، حماية النموذج من الإغلاق العرَضي، بقاء ارتباط نشاط عام دراسي سابق بشعبته عند التعديل، الروابط العميقة من التقويم ولوحة التحكم، التقارير (معاينة وPDF وExcel وطباعة الورقة، ونطاق «كل الفترات»)، الإلغاء والحذف بتأكيد، وفحص axe للنوافذ المنبثقة.
- **مسح بصري:** 15 صفحة × (فاتح/داكن) × (حاسوب/جوال) = 60 لقطة في `e2e-output/` مع فحص التمرير الأفقي، وأسماء العناصر التفاعلية، ومخالفات إمكانية الوصول الآلية (axe)، وغياب أخطاء الكونسول وردود HTTP غير المتوقعة.

يشغّل CI (`.github/workflows/ci.yml`) الفحص والاختبارات والبناء ثم الاختبار الشامل عند كل دفع.

## الأمان وحماية بيانات الطلاب

الملخص (التفصيل في [SECURITY](docs/SECURITY.md)):

- **عزل المعلمين:** كل جدول بيانات يحمل `owner_id`، وكل دالة خدمة تأخذ `ownerId` وتقيّد به الاستعلام؛ الوصول لمورد معلم آخر يُرجع 404.
- **كلمات المرور:** scrypt (64 م.ب لكل تجزئة) بملح عشوائي، حد أدنى 8 أحرف مع رفض الشائعة، قفل مؤقت متصاعد بعد 5 محاولات فاشلة، رسالة دخول موحّدة (لا تكشف وجود الحساب).
- **الجلسات:** رمز عشوائي في كوكي `HttpOnly` + `SameSite=Lax` (+`Secure` و`__Host-` عند HTTPS)، يُخزَّن في القاعدة **مُجزَّأً** (SHA-256)، ويمكن للمستخدم إنهاء جلساته على الأجهزة الأخرى.
- **CSRF وXSS:** رأس مخصص إلزامي + فحص Origin، وCSP صارمة بلا سكربتات مضمّنة، وتقارير HTML تُولَّد بنمط هروب تلقائي.
- **حماية الاستعلامات:** كل المدخلات تمر بمخططات Zod، والاستعلامات معلَّمة (Drizzle) — لا SQL مدمج بنصوص المستخدم.
- **سجل العمليات** بلا أسماء طلاب أو درجات، والنسخ الاحتياطية قابلة للتشفير.
- **الخصوصية:** لا تتبّع ولا خدمات خارجية ولا خطوط CDN؛ كل شيء يعمل من الخادم نفسه.

**ما لا يغطيه التطبيق بنفسه** (مسؤولية النشر): تشفير قرص الخادم، وHTTPS، وتحديثات النظام، ونسخ احتياطي خارج الخادم. القاعدة نفسها غير مشفّرة على القرص؛ راجع [SECURITY](docs/SECURITY.md#حدود-الحماية).

## النسخ الاحتياطي

- **تلقائي:** كل 24 ساعة افتراضيًا (يُضبط)، يحتفظ بآخر 14 نسخة.
- **قبل كل ترقية** لقاعدة البيانات و**قبل كل استعادة** تُؤخذ نسخة أمان تلقائيًا.
- كل نسخة تُفحَص سلامتها (`integrity_check`) قبل اعتمادها.
- من الواجهة (للمدير): إنشاء، تنزيل، حذف، **استعادة** من الخادم أو من ملف مرفوع (بتأكيد كتابي).
- من سطر الأوامر: `npm run cli -- backup` و`restore <ملف> --yes`.
- تشفير اختياري AES-256-GCM بتعيين `BACKUP_PASSPHRASE`.

التفاصيل وخطة التعافي من الكوارث: [BACKUP](docs/BACKUP.md).

## التوسّع مستقبلًا

أُنشئ النظام ليتّسع دون إعادة بناء: وحدة جديدة = مجلد في `modules/` + سطر في السجل + صفحة وعنصر تنقّل. الدليل الكامل بمثال وحدة «سجل المختبر والأنشطة» الفعلية: [ADDING-A-MODULE](docs/ADDING-A-MODULE.md).

## القيود المعروفة

صراحةً، وبلا تجميل:

1. **الوحدات غير المنفّذة:** الحضور اليومي، المساعد الذكي (نقطة توسعة فقط).
2. **SQLite وخادم واحد:** مناسب لمعلم أو مدرسة. لا تعدد خوادم ولا توسّع أفقي؛ الانتقال لقاعدة أخرى عمل مستقل.
3. **تصدير PDF يحتاج Chromium** على الخادم. بدونه: «طباعة» ثم «حفظ كـ PDF» من المتصفح، و«Excel» يعمل دائمًا.
4. **لا استعادة كلمة المرور بالبريد** (لا خدمة بريد مدمجة): المدير يعيّن كلمة مؤقتة، أو `cli reset-password`.
5. **القاعدة غير مشفّرة على القرص** (النسخ الاحتياطية فقط قابلة للتشفير) — استخدم تشفير القرص في الخادم.
6. **لا تصدير/استيراد كامل لبيانات معلم واحد** (الحق في نقل البيانات) خارج النسخ الاحتياطي الكامل والتقارير.
7. **لم تُختبر على أجهزة آبل أو متصفحات غير Chromium** في بيئة التطوير؛ التصميم قياسي ويُتوقع أن يعمل، لكن لا ادّعاء باختبار.
8. **الملفان `Dockerfile` و`docker-compose.yml` لم يُبنَيا** هنا (انظر أعلاه).
9. حقول التاريخ والوقت الأصلية في المتصفح تعرض بتنسيق نظام المستخدم (قد تظهر الأرقام لاتينية في بعض الأنظمة).
